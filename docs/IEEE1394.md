# IEEE-1394 wire-format evidence

- Status: Stored wire representation not yet identified; decoder deferred
- Last updated: 2026-08-28

## Purpose

This document records the evidence needed to identify and decode an
IEEE-1394 wire representation after a capture container has exposed its stored
bytes. It does not define BIE fields. The internal BIE grammar, timestamps,
status word, lengths, and termination rules belong exclusively in
[`BIE-FORMAT.md`](BIE-FORMAT.md).

## Current evidence gap

The supplied recorder summary labels the captured data as IEEE 1394, but that
label does not identify which part of the wire exchange was stored. The current
BIE stored-data region does not begin with an identifiable complete IEEE-1394
link packet. No link header, header CRC, or data CRC has been located around
the application bytes.

The available bytes therefore do not yet establish whether the internal
recording retained a physical-layer event, link packet, asynchronous stream,
completed transaction, normalized message, or another representation. The
absence of visible wire framing may mean it was removed or transformed, but
the current evidence cannot determine how.

## Evidence needed to define the decoder

Before an IEEE-1394 decoder contract is added, obtain:

- the internal definition of the IEEE-1394 representation stored in BIE;
- the exact applicable IEEE-1394 revision;
- a controlled packet with known source, destination, transaction or stream
  type, payload length, and expected CRC values;
- an independent wire/analyzer view of the same event; and
- examples covering every retained event family, including any bus-reset,
  acknowledge-only, prefix-only, PHY, asynchronous, or isochronous records.

## Current conclusion

No IEEE-1394 wire-packet layout or decoder behavior is currently specified.
BIE stored data remains opaque at the container boundary. When controlled
evidence identifies the stored representation, this document will become the
wire-level specification and will define field layout, byte/bit numbering,
CRC coverage, supported packet families, and unsupported cases.

AS5643-derived observations that begin inside the opaque stored region remain
separate in [`AS5643.md`](AS5643.md).
