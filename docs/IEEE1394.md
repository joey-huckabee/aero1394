# IEEE-1394 capture evidence

- Status: Preliminary comparison; no IEEE-1394 packet decoder implemented
- Last updated: 2026-08-28

## Boundary

BIE is a recorder container, not the IEEE-1394 wire format. The current BIE
record exposes a timestamp, a raw status/length word, and opaque stored data.
IEEE-1394 interpretation is a downstream operation and must remain usable with
future non-BIE input adapters.

## Current observations

The BIE status/length values observed so far are `0x00000074` and
`0x40000074`. Their low 16 bits select exactly 116 following bytes. The shape
resembles the IRIG 106 IEEE-1394 Format 1 intra-packet status/length word, which
contains an upper status region and lower data length.

That resemblance is a comparison lead only:

- IRIG 106 container structures use their own specified byte order and time
  representation;
- the observed BIE timestamp is big-endian Unix seconds plus microseconds;
- no Chapter 10 packet header surrounds the observed records; and
- the meaning of the BIE `0x40000000` status bit is unknown.

The supplied stored data does not begin with an identifiable complete
IEEE-1394 link packet. No link header, header CRC, or data CRC is visible around
the application data. DAP tooling can export data-only representations, so
missing link framing is compatible with a normalized recorder/export path but
does not prove one.

## Implementation constraints

- Do not call the BIE status/length word a Chapter 10 Message ID Word.
- Preserve its upper bits as raw recorder status until independently decoded.
- Do not synthesize missing IEEE-1394 headers or CRCs.
- Do not run an IEEE-1394 parser merely because the file extension or summary
  says IEEE 1394; require a supported captured representation.
- Record the exact IEEE-1394 and IRIG 106 revisions before implementing
  normative bitfields, packet lengths, or CRC coverage.
- Correlate the same interval with vendor text, CSV, raw, `.fsp`, or `.rgn`
  output before stabilizing captured-packet semantics.

The public comparison research and sources remain in `BIE-FORMAT.md` because
they help distinguish container identities. Verified IEEE-1394 structures will
move here as downstream decoding begins.
