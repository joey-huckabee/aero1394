# IEEE-1394 capture evidence

- Status: Preliminary comparison; no IEEE-1394 packet decoder implemented
- Last updated: 2026-08-28

## Boundary

BIE is an internal capture container, not the IEEE-1394 wire format. The
current BIE record exposes a timestamp, a raw status/length word, and opaque
stored data.
IEEE-1394 interpretation is a downstream operation and must remain usable with
future non-BIE input adapters.

## Current observations

The BIE status/length values observed so far are `0x00000074` and
`0x40000074`. Their low 16 bits select exactly 116 following bytes. The meaning
of the BIE `0x40000000` status bit needs resolution through the controlled
investigation in [`ROADMAP.md`](../ROADMAP.md). No IEEE-1394 status or event
meaning may be inferred from that flag until independent evidence establishes
the mapping.

The supplied stored data does not begin with an identifiable complete
IEEE-1394 link packet. No link header, header CRC, or data CRC is visible around
the application data. Missing link framing is compatible with an internal
normalization step but does not prove how the source representation was
transformed.

## Implementation constraints

- Preserve the BIE upper bits under a neutral unresolved-flags name until
  independently decoded.
- Do not synthesize missing IEEE-1394 headers or CRCs.
- Do not run an IEEE-1394 parser merely because the file extension or summary
  says IEEE 1394; require a supported captured representation.
- Record the exact IEEE-1394 revision before implementing normative bitfields,
  packet lengths, or CRC coverage.
- Correlate the same interval with an independently decoded view before
  stabilizing captured-packet semantics.

Future container adapters and their source research are kept in
[`ROADMAP.md`](../ROADMAP.md). Verified IEEE-1394 structures will be recorded
here as downstream decoding begins.
